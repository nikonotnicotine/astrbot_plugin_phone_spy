## 前置条件

- **iOS 18.4 或更新版本**（邮件自动化功能要求）
- **必须使用 iCloud 邮箱作为收件人**（形如 `你的名字@icloud.com`）
  - 为什么必须是 iCloud：因为 iOS 邮件自动化只对 iCloud 邮件的**推送**即时响应（几秒内到达）
  - QQ 邮箱、Gmail 等非 iCloud 邮箱，iPhone 需要**轮询**才能收到邮件，延迟 5-15 分钟
- 发件方可以是任何邮箱（QQ、163、Gmail、iCloud 都行），最简单的方案是 iCloud 自己给自己发

## 本地部署配置

**适用场景：** AstrBot 运行在家里的 Windows/Mac/Linux 电脑上，和 iPhone 在同一局域网内。

### 第一步：在 AstrBot 控制面板配置插件

打开 AstrBot 控制面板 → 插件管理 → 找到 `astrbot_plugin_phone_spy` → 点击配置。

按下表填写：

| 配置项 | 填什么 | 示例 | 说明 |
|--------|--------|------|------|
| `smtp_host` | SMTP 服务器地址 | `smtp.mail.me.com`（iCloud）<br>`smtp.qq.com`（QQ 邮箱）<br>`smtp.163.com`（163 邮箱） | 用哪个邮箱**发**触发邮件，就填对应的 SMTP 地址 |
| `smtp_port` | SMTP 端口 | `587`（iCloud 必须用 587）<br>`465`（QQ/163 用 465） | iCloud 必须 587，其他邮箱一般 465 |
| `smtp_user` | SMTP 登录账号 | `你的邮箱@icloud.com` | 完整邮箱地址（这个地址稍后要填进 iPhone 自动化的"发件人"条件） |
| `smtp_password` | SMTP 授权码 | `abcd-efgh-ijkl-mnop` | **不是登录密码！**<br>iCloud：到 appleid.apple.com → 安全 → App 专用密码（需先开启双重认证）<br>QQ 邮箱：设置 → 账户 → 开启 SMTP 后获取授权码 |
| `icloud_address` | 收件人 iCloud 邮箱 | `你的名字@icloud.com` | **必须是 iCloud 邮箱**，触发邮件发到这里，iPhone 收到后自动截屏<br>可以和 `smtp_user` 填成同一个地址（自己发给自己） |
| `webhook_port` | 接收服务端口 | `8080` | 插件在这个端口开 HTTP 服务等 iPhone 回传截图<br>若端口被占用请换一个（如 9001） |
| `webhook_path` | 接收路径 | `/phone/screenshot` | **只填路径**，不要填完整 URL<br>⚠️ 开头必须有 `/` |
| `webhook_secret` | 校验密钥 | 随机 16 位以上字符串 | 在终端执行 `openssl rand -hex 24` 生成一个<br>这个密钥稍后要填进 iPhone 快捷指令 |
| `vision_api_url` | 识图模型 API | `https://api.openai.com/v1/chat/completions` | OpenAI 兼容格式的视觉模型 API 地址 |
| `vision_api_key` | 识图模型密钥 | `sk-...` | 对应 API 的密钥 |
| `vision_model` | 识图模型名称 | `gpt-4o` | 必须是支持看图的模型（如 gpt-4o、gemini-2.0-flash-exp、qwen-vl-plus） |
| `timeout_seconds` | 超时时间（秒） | `90` | 从发邮件到收到截图的最长等待时间<br>正常 10-30 秒完成，建议留 60-120 |
| `forward_image` | 是否转发截图给你 | `false` | 开启后 AI 查岗时会把截图也发到聊天里 |
| `auto_fallback` | 手机失败时改查电脑 | `true` | 手机没响应时自动调用电脑查岗兜底（需安装 screen_monitor 插件） |

**配置完成后，点击"保存"并重新加载插件。**

---

### 第二步：在 iPhone 上创建快捷指令

#### 2.1 新建快捷指令（负责截图和上传）

1. 打开 **快捷指令 App** → 点右上角 `+` 新建
2. 按顺序添加以下动作：

   **动作 1：截屏**
   - 搜索并添加 **"截屏"** 动作（在"媒体"分类下）

   **动作 2：转换图片格式**
   - 搜索并添加 **"转换图像"**
   - 格式选择 **JPEG**
   - 质量设为 **0.5**（压缩以加快上传）

   **动作 3：上传到服务器**
   - 搜索并添加 **"获取 URL 内容"**
   - **URL** 填：`http://你电脑的局域网IP:8080/phone/screenshot`
     - 例如：`http://192.168.1.100:8080/phone/screenshot`
     - 如何查看电脑的局域网 IP：
       - Windows：`ipconfig` 看 IPv4 地址
       - Mac：系统设置 → 网络 → 看当前连接的 IP
       - Linux：`ip addr` 或 `ifconfig`
   - **方法** 改为 **POST**
   - **请求体** 选择 **"表单"**
   - 点击 **"添加新字段"** 或 `+` 号，添加两个字段：

     **字段 1（校验密钥）：**
     - **左边（字段名）**：填 `secret`（全小写，不要填中文"密钥"）
     - **右边（字段值）**：类型选 **"文本"**，内容填你在插件配置里设置的 `webhook_secret`
       - 例如：`a7f3k9m2q5x8w1z4`

     **字段 2（截图文件）：**
     - **左边（字段名）**：填 `image`（全小写）
     - **右边（字段值）**：类型选 **"文件"**，点击选择 **"转换后的图像"**（上一步转换的 JPEG）

3. 将快捷指令命名为 **"手机查岗截图"**
4. 点右上角"完成"保存

#### 2.2 新建邮件自动化（负责触发截图）

1. 打开 **快捷指令 App** → 底部点 **"自动化"** 标签
2. 点右上角 `+` → 选 **"个人自动化"**
3. 选择 **"邮件"** → **"收到新邮件时"**
4. 配置触发条件（**三个条件都要设置**）：
   - **发件人**：包含 → 填你在插件配置里设置的 `smtp_user`（发触发邮件的账号）
   - **主题**：包含 → 填 `PHONESPY_TRIGGER`（全大写）
   - **收件人**：包含 → 填你的 iCloud 邮箱地址
5. 点"下一步"
6. 点"添加操作" → 搜索并选择你刚创建的快捷指令 **"手机查岗截图"**
7. **⚠️ 重要：** 关闭"运行前询问"开关，确保 **"立即运行"** 开启
8. 点"完成"保存

---

### 第三步：测试

1. 确认 AstrBot 日志显示：`📡 截图接收服务已启动: http://0.0.0.0:8080/phone/screenshot`
2. 对 AI 说"看看我手机"
3. 预期流程：
   - 插件发送触发邮件 → iPhone 收到邮件（几秒内）
   - 邮件自动化触发 → 快捷指令运行 → 截屏 → 上传
   - 服务器收到截图 → 视觉模型分析 → AI 回复屏幕内容

**如果超时收不到截图：**
- 确认邮件是否到达 iCloud 邮箱（打开邮件 App 查看）
- 确认快捷指令的邮件自动化是否设置为 **"立即运行"**
- 确认 iPhone 和电脑在同一局域网，IP 地址填对了
- 用浏览器访问 `http://你的IP:8080/phone/screenshot`，应该返回 404 或 405（说明服务在运行）

### 第二步：配置 VPS 网络访问

#### 方案 A：Tailscale（推荐）

**优点：** 不需要开放公网端口，流量加密，无需维护 IP 白名单

**步骤：**

1. 在 VPS 和 iPhone 上都安装 Tailscale，加入同一个账户
2. 记下 Tailscale 分配给 VPS 的 IP（形如 `100.x.x.x`）
3. iPhone 快捷指令里的 URL 填：`http://100.x.x.x:9001/phone/screenshot`
4. VPS 防火墙**不需要**放行 9001 端口（Tailscale 走加密隧道）

#### 方案 B：公网 IP + 防火墙白名单

**优点：** 不需要额外软件，直接用公网 IP 访问

**步骤：**

1. **在服务商控制台配置安全组/防火墙**
   - 添加入站规则：
     - **协议**：TCP
     - **端口**：你配置的 `webhook_port`（如 9001）
     - **来源**：**只允许你 iPhone 所在网络的公网 IP**
       - 查看 iPhone 的公网 IP：用 iPhone 浏览器访问 `https://ip.sb` 或 `https://ifconfig.me`
       - ⚠️ **不要填 `0.0.0.0/0`**（会开放给全世界所有人）
   - 保存规则

2. **注意事项：**
   - 家庭宽带的公网 IP 可能会变化（通常几天到几周变一次）
   - IP 变化后需要手动更新防火墙规则
   - 如果觉得维护麻烦，建议用方案 A（Tailscale）

3. **为什么不建议直接开放 0.0.0.0/0？**
   - 公网上有大量自动扫描器，会持续向所有开放端口发请求
   - 虽然插件靠 `webhook_secret` 鉴权（不匹配返回 403），不会被轻易伪造
   - 但无谓的扫描流量会写满日志、消耗带宽，偶尔触发服务商告警
   - IP 白名单可以从源头阻断这些噪音

### 第四步：VPS 上测试连通性

在 VPS 终端执行：

```bash
curl -X POST http://127.0.0.1:9001/phone/screenshot \
  -F "secret=你的webhook_secret" \
  -F "image=@/tmp/test.jpg"
```

**预期结果：**
- 返回 `ok` 或 `200 OK`：成功
- 返回 `403 forbidden`：密钥不对，检查 `secret` 值
- 返回 `404 not found`：路径不对，检查 `webhook_path` 是否以 `/` 开头
- `Connection refused`：端口未放行或服务未启动

## iOS 快捷指令与自动化设置

本节把所有手机功能的 iOS 快捷指令和邮件自动化配置集中在这里。每个功能都需要在插件配置中打开对应开关，并在 iPhone 上建立对应的邮件自动化。

### 开始之前，准备两样东西

- **你的 IP**：Windows 命令行输入 `ipconfig`，找到「IPv4 地址」，形如 `192.168.1.100`。下面所有 `http://你的IP:8080` 都替换成它。
- **你的密钥**：就是插件配置里的 `webhook_secret`。请填写 16 位以上的随机字符，例如 `a7f3k9m2q5x8w1z4`，并在快捷指令中使用完全相同的值。
- iPhone 与运行 AstrBot 的电脑需要连在同一个 Wi-Fi；VPS 部署则使用 VPS 的可访问地址。

### 建邮件自动化的固定步骤

除特别说明外，每个功能的邮件自动化都按以下步骤开始：

1. 打开「快捷指令」App → 底部「自动化」→ 右上角「+」。
2. 触发条件选择「邮件」。
3. 勾选「发件人」，填插件配置里的 `smtp_user` 邮箱地址。
4. 勾选「主题」，填该功能对应的主题词（每节都会列出）。
5. 打开「立即运行」，关闭「运行前询问」。
6. 点「下一步」，进入添加动作的界面。
7. 按下面的「动作 1、动作 2……」添加动作，完成后点右上角「完成」。

### 网易云音乐

以下功能都要先打开插件配置 `netease_music.enable_music_control` 总开关。

#### 播放每日推荐

- 插件开关：`enable_daily_recommend`
- 主题：`ASTRBOT_MUSIC_DAILY`

动作 1：搜索「网易云」，选择「播放每日推荐（启动 App）」，`scene` 参数留空。

#### 播放私人漫游

- 插件开关：`enable_personal_fm`
- 主题：`ASTRBOT_MUSIC_FM`

- 插件开关：`enable_alarm`

2. 动作 2：搜索「创建闹钟」，在时间字段插入「文本」变量。

2. 搜索「开关闹钟」，在动作里选择「关闭」，时间字段插入「文本」变量。

如果时间字段不接受文本变量，先用「日期」动作把文本转换成日期，再将日期插入「开关闹钟」。快捷指令 App 里同名动作默认会列出设备上已有的闹钟，建议先手动运行一次，确认时间匹配和「开启/关闭」状态都正确后再保存。

### 配完之后

1. 插件配置改完后，去 AstrBot 管理面板点击插件「重载」。
2. 建议按顺序测试：先配「锁定屏幕」验证邮件链路，再配微信截图，再配电量，最后按需添加其他功能。
3. 不要一次全配完再测试；每配好一个功能就单独验证一次。
4. 可以对 AI 直接说「放首晴天」「我手机还有多少电」「看看我微信」「明早七点半叫我起床」「把明早七点半的闹钟关了」等自然语言。
5. 打开 App、截图等动作需要 iPhone 解锁亮屏；锁屏和播放/暂停在锁屏状态下也可以使用。

### 单独测试与排错

- 快捷指令 App 里可以点进自动化，使用右下角播放按钮手动运行。
- 播歌和闹钟自动化依赖邮件正文，手动运行时可能因没有输入正文而失败；截图和锁屏自动化可以直接手动测试。
- 没收到邮件：检查 SMTP 配置；iCloud 发信使用 App 专用密码，端口通常为 `587`。
- 收到邮件但手机没反应：检查主题词大小写、下划线、发件人，以及「立即运行」和「运行前询问」设置。
- 手机有动作但 AI 超时：检查截图 URL、IP、端口、密钥，以及 `image` 是否为「文件」字段；手机端不要把 URL 写成 `127.0.0.1`。
- 经常超时：把插件 `timeout_seconds` 调到 `120`，并把截图自动化里的「等待」从 3 秒调到 5 秒。

## 记忆记录（让记忆插件记住 AI 看到了什么）

**要解决的问题：** 插件的工具调用和识图结果不走正常的对话流程，`astrbot_plugin_conversation_logger`、`astrbot_plugin_romantic_memory` 这类记忆插件抄不到，AI 过一会儿就忘了自己刚看过你手机。

**做法：** 插件在记忆插件抄写之前，临时往 AI 的回复前面贴一条 `[系统提示:...]`，等记忆插件抄完再撕掉。**两个记忆插件一行代码都不用改。** 这条记录既不会发给你，也不会进入 AI 的对话上下文，只有记忆插件看得到。

记忆文件里会出现这样的行：

```
[系统提示:你操控用户的手机使用了播放指定歌曲功能，播放了《You Like It》 - Omarion]
[系统提示:你操控用户的手机使用了查看支付宝账单功能，识别截屏结果:今天在瑞幸花了 38 元……]
[系统提示:用户发送了一张图片，识别结果:一只橘猫躺在键盘上……]
```

配置项都在插件配置的 **记忆记录** 分组下：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `enable` | `true` | 总开关 |
| `record_tools` | `true` | 记录手机操控（全部 18 个工具） |
| `record_user_images` | `true` | 记录**你**在聊天里发的图片。⚠️ 每张图额外消耗一次识图 API 调用；识别在后台和 AI 回复同时跑，基本不拖慢回复 |
| `private_only` | `true` | 只在私聊里记录（两个记忆插件本来也只记私聊，群聊里做这些是白费 API 调用） |
| `max_detail_chars` | `0` | 单条记录的内容长度上限，`0` = 不截断 |
| `template` | 见配置 | 手机操控记录的格式，变量 `{{feature}}` `{{detail}}` |
| `user_image_template` | 见配置 | 用户图片记录的格式，变量 `{{detail}}` |
| `user_image_prompt` | 见配置 | 描述用户图片时给识图模型的提示词 |
| `user_image_timeout` | `45` | 等识图结果的上限，超时就放弃这条记录，不影响正常回复 |

识图复用 `vision_api_url` / `vision_api_key` / `vision_model` 那套配置，不用另外填。视觉模型没配置时自动跳过图片记录。

## 整合查岗（一次查完多个项目）

**默认关闭。** 开启前请先确认单个查看类功能都已经跑通。

**要解决的问题：** 一个个工具让 AI 自己挑着调，一是工具定义占 token，二是工具调用有 120 秒超时上限，连着查几项必然超时。

**做法：不用工具，改用暗号。** 插件只往系统提示里塞一句话，告诉 AI「你可以查岗」。AI 想查岗时就在回复末尾写一个标记 `[查询用户手机APP]`，插件抓到标记后当场把它剥掉（你和记忆插件都看不到），然后另起一个后台任务去查。AI 该回的话已经回给你了，一点都不卡。

**⚠️ 全主动：只有 AI 会触发。** 你说任何话都不会触发它。

一次完整的流程（假设 `features` 填了支付宝账单、淘宝购物车、抖音个人主页、位置）：

```
你：在干嘛呢
  ↓ 插件在系统提示里塞一句「你可以查岗」（只这一句，省 token）
AI：想你呢 [查询用户手机APP]
  ↓ 插件剥掉标记 → 你收到的是「想你呢」
  ↓ 插件开后台任务，你这边已经收到回复了，不卡
后台：截支付宝 →(5秒)→ 截淘宝购物车 →(5秒)→ 截抖音 →(5秒)→ 取位置
  ↓ 三张图打包成一次识图请求
  ↓ 识图结果 + 位置 拼成一段话，问 AI 一次
AI：你今天在瑞幸又花了 38，购物车里那双鞋还躺着呢，还在公司加班？
  ↓ 用平台原生动作发给你（不经过 send_message）
```

**这期间你又发消息了怎么办？** 默认会把你这条消息**按住**，等查岗全部结束再交给 AI 回复 —— 这样 AI 回复时已经知道自己刚看到了什么，不会前后脱节。最多按住 `hold_max_seconds` 秒（默认 600），超时直接放行，不会把消息吞掉。插件重载/停用时也会立刻放行。

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `enable` | `false` | 总开关 |
| `features` | 空 | **要查的项目，每行一个，按填写顺序查。**<br>可用：当前屏幕、微信、支付宝账单、B站历史、抖音私信、抖音个人主页、淘宝订单、淘宝购物车、位置、电量<br>简称也认（「支付宝」「购物车」「定位」）<br>⚠️ 不含网易云、闹钟、锁屏 —— 那些是操控不是查岗 |
| `interval_seconds` | `5` | 每项之间的间隔，给快捷指令留出切 App 的时间。填太小前后两张图容易串台 |
| `streaming` | `false` | **不是 API 的流式输出。**<br>关闭（推荐）：全部查完 → 所有截图一次性识图 → 只问 AI 一次 → 发 1 条消息<br>开启：每截一张图就识一次、问一次、发一条，查 4 项 = 4 条消息 + 4 次识图 + 4 次 AI 调用，token 约四倍 |
| `suppress_other_tools` | `true` | 撤掉其他查看类工具的注入，这是省 token 的关键。网易云、闹钟、锁屏不受影响 |
| `private_only` | `true` | 只在私聊里查岗。群聊里主动播报你的支付宝账单不太妙 |
| `hold_user_message` | `true` | 查岗期间按住你的新消息（见上文） |
| `hold_max_seconds` | `600` | 最多按住多久的保险绳 |
| `cooldown_seconds` | `300` | 冷却时间。上一轮查完后这么久内既不查岗、也不给 AI 注入那条提示，避免它上瘾式连查。`0` = 不冷却 |
| `history_rounds` | `10` | 查岗后主动说话时带上最近几轮对话（带人设 + 历史，免得人格分裂）。`0` = 只带人设 |
| `vision_timeout_seconds` | `180` | 批量识图超时。多张图一次识别比单张慢得多，别填太小。只在关闭流式时生效 |
| `marker` | `[查询用户手机APP]` | 暗号。改了这里，`hint` 里的那句也要跟着改成同一个 |
| `hint` | 见配置 | 注入给 AI 的那一条提示。留空 = 不注入（AI 就不知道自己能查岗） |
| `round_prompt` | 见配置 | 流式模式每一项的提示词，变量 `{{index}}` `{{total}}` `{{feature}}` `{{result}}` |
| `final_prompt` | 见配置 | 一次性模式的总结提示词，变量 `{{total}}` `{{result}}` |
| `vision_batch_prompt` | 空 | 留空用内置的。变量 `{{count}}` `{{items}}`。必须要求模型按「1. 项目名：」逐条回答，否则插件切不开各项结果，只能整段附在最后 |
| `reply_template` | 见配置 | 主动发言写进记忆的格式，变量 `{{detail}}` |

**不需要新建任何快捷指令。** 整合查岗复用各功能原有的邮件主题（`ASTRBOT_ALIPAY`、`ASTRBOT_TAOBAO_CART`……），你按 [iOS 快捷指令与自动化设置](#ios-快捷指令与自动化设置) 建好的自动化直接就能用。但**填进 `features` 的项目，对应的自动化必须先建好**，否则那一项只会等到超时。

**第一次开建议只填一项**（比如只填「电量」，它最快也最不容易出错），确认能收到主动消息之后再往上加。

**迟到的截图怎么处理：** iPhone 回传截图时没法带上「这是第几张」，插件只能按先后顺序认领。所以某一项超时后会留一张「迟到条」，之后到达的第一张图只在「不可能属于当前项目」时才丢弃（当前没人在等，或者当前项目才发出去不到 8 秒）；迟到条本身也会过期作废，不会误伤后面正常的截图。

## 常见问题

### 1. 邮件会不会自动删除？

**不会。** 插件只通过 SMTP 发送触发邮件，不会登录 iCloud 读取、移动或删除邮件。触发邮件会一直留在收件箱，需要手动清理。

**建议：**
- 在 iCloud 邮件网页端建立规则，将主题包含 `PHONESPY_TRIGGER` 的邮件自动移到专用文件夹
- 先不要设置自动删除，确认自动化稳定后再定期清空文件夹

### 2. 为什么快捷指令报"密钥不匹配"？

**最常见原因：** 表单字段名填错了。

- ❌ 错误：字段名填成了"密钥"或"secret="
- ✅ 正确：字段名必须是 `secret`（小写），字段值才是密钥本身

检查方法：
- 打开快捷指令，点"获取 URL 内容"
- 展开"请求体"，确认有两个字段
- 第一个字段**左边**应该显示 `secret`（不是密钥值）
- 第一个字段**右边**才是密钥值（如 `a7f3k9m2q5x8w1z4`）

### 3. 超时时间设置成 60 秒，是不是要等 60 秒才发送？

**不是。** `timeout_seconds` 只是"最多等 60 秒"的意思，截图到达后会**立刻处理**，不会继续等。

正常流程：
- 邮件发出 → iPhone 收到（2-5 秒）→ 截屏上传（5-20 秒）→ 服务器立刻处理
- 总耗时通常 10-30 秒，远远不到 60 秒

只有当截图**真的没到**时，才会等到 60 秒超时。

### 4. VPS 的 `webhook_path` 到底怎么填？

**只填路径部分，不填完整 URL。**

- ❌ 错误：`/http://182.64.943.9:9001/phone/screenshot`
- ❌ 错误：`http://182.64.943.9:9001/phone/screenshot`
- ✅ 正确：`/phone/screenshot`

完整 URL 只在 iPhone 快捷指令里填，配置文件里只填路径。

### 5. 能否直接导入快捷指令？

**不能通过普通文件直接导入。** Apple 的快捷指令分享链接必须由 iPhone 上的"快捷指令" App 生成，尤其是"获取 URL 内容"的 `multipart/form-data` 文件字段，需要由 iOS 写入。

**建议：**
1. 按上面步骤手动创建一次（通常只需几分钟）
2. 创建后在 iPhone 上点"分享" → "复制 iCloud 链接"
3. 以后在其他设备打开这个链接就能导入
4. 导入后只需检查服务器地址、密钥是否正确

### 6. 内存会不会爆炸？

**正常使用下不会。** 插件已做限制：

- 单个请求体最大 **16 MB**
- 单张图片最大 **16 MB**
- 最多同时保留 **8 个**等待中的查岗请求
- 超时、成功和插件重载都会自动清理

iPhone JPEG 截图通常只有几百 KB 到几 MB，对 1-2 GB 的 VPS 压力很小。

### 7. iCloud 邮件存储会不会满？

**触发邮件本身很小**（几百字节），不会占用明显空间。插件不会把截图上传到 iCloud 邮箱，截图只在 VPS 内存里临时保存，分析完就释放。

### 8. 整合查岗开了之后，"看看我微信"这类还能用吗？

**不能直接用了。** `suppress_other_tools` 默认会撤掉查看类工具的注入，AI 手上没这些工具了，只能靠自己发暗号整体查一遍 —— 这就是它省 token 的地方。

想两种都留着，把 `suppress_other_tools` 关掉即可，代价是 token 涨回去。**网易云放歌、闹钟、锁屏不受影响**，照常能用。

### 9. 整合查岗为什么不用工具调用？

**工具调用有 120 秒超时上限。** 整合查岗要一项一项连着查，四项加上间隔就要一两分钟，必然超时。改成"AI 写暗号 + 插件后台跑"就没有这个限制了，AI 也不用捧着电话干等。

### 10. 查岗后 AI 主动说的那句话，记忆插件记得到吗？

**记得到。** 那句话是插件直接调 AI 生成的，不走正常对话流程，记忆插件本来抄不到，所以插件会自己补一条 `[系统提示:你查岗完用户的手机后，主动对用户说了:...]`，格式见 `reply_template`。

后台查岗攒下的记录会等你**下次说话**时一次性挂上去（那时候记忆插件才在工作）。每个会话最多攒 50 条，不会无限堆积。

### 11. 记录会不会把记忆文件写爆？

每条记录都会被压成单行，`max_detail_chars` 可以限制单条内容长度（默认 `0` 不截断，担心的话填 200）。识图结果通常几十到几百字，正常聊天量下影响很小。

### 12. 主动消息发不出去？

日志里如果出现 `❌ 整合查岗：当前平台没有 call_action`，说明当前平台适配器不支持原生发送动作（插件走的是和 `astrbot_plugin_reply_quote` 的 `[拍一拍对方]` 同一条路，目前只在 aiocqhttp / OneBot 上验证过）。这种情况下查岗内容仍会补进上下文和记忆，只是不会单独发一条消息给你。

## 安全建议

1. **`webhook_secret` 必须随机且足够长**（≥16 字符）
   ```bash
   openssl rand -hex 24
   ```

2. **保护 VPS 上的配置文件**（里面有密钥明文）
   ```bash
   chmod 600 data/config/astrbot_plugin_phone_spy_config.json
   ```

3. **VPS 部署时不要开放 0.0.0.0/0**
   - 用 Tailscale 或 IP 白名单限制访问
   - `webhook_secret` 是最后一道防线，但白名单能从源头阻断扫描流量

4. **定期检查 VPS 日志**
   - 如果看到大量 403 请求，说明有人在扫描你的端口
   - 考虑更换端口或启用 Tailscale
